# テスト計画

## 前提とリスク

使う場所は**ネットにつながらない電子カルテ PC**、使う人は**パソコンに詳しくない利用者**、扱う書類は**診療情報**。
そこから、テストで特に守るものを次の順に決めた。

1. **通信しないこと** — 1 バイトでも外に出たら導入できない
2. **元の書類を壊さない・消さないこと** — 出力で上書きしない
3. **読み取った内容が正しいこと** — 誤認識はゼロにできないので、少なくとも「読めた文字が欠けない・並びが崩れない」
4. **1 ファイルの失敗で全体が止まらないこと**、失敗したら理由が日本語でわかること
5. **exe にしたあとも動くこと** — 開発環境では動くが配布物で壊れる、が一番気づきにくい

## テストの構成

```
        /  配布物スモーク  \     exe + 同梱 Tesseract で 3 形式を実際に出力 (CI の Windows で毎回)
       /  OCR 結合 / 画面   \    本物の Tesseract・本物の Tk で一連の流れ
      /       単体テスト      \   レイアウト・整形・書き出し・設定・読み込み (速い、Tesseract 不要)
```

| 対象 | 種類 | ファイル | Tesseract | 主に守るもの |
| --- | --- | --- | --- | --- |
| 日本語の整形 (`textutil`) | 単体 | `test_textutil.py` | 不要 | 3 |
| 行・列の組み立て (`layout`) | 単体 | `test_layout.py` | 不要 | 3 |
| ファイル読み込み (`loader`) | 単体 | `test_loader.py` | 不要 | 4 |
| 書き出し (`exporters`) | 単体 | `test_exporters.py` | 不要 | 3 |
| 設定 (`settings`) | 単体 | `test_settings.py` | 不要 | 4 |
| 処理の流れ (`processor`) | 単体 (代役エンジン) | `test_processor.py` | 不要 | 1, 2, 4 |
| 実際の文字認識・CLI | 結合 | `test_ocr_integration.py` | **必要** | 3, 4 |
| 画面 | 結合 | `test_gui.py` | 不要 (代役) | 4 |
| exe | スモーク | `smoke_bundle.py` | 同梱版 | 5 |

## 主なテストケース

- **通信しない**: `socket.socket` / `create_connection` を呼んだら失敗するようにして、3 形式すべてを出力 (`test_processing_never_touches_the_network`)
- **上書きしない**: 同名ファイルがあれば `(2)`, `(3)`…、PDF→PDF は `_文字起こし` を付ける
- **日本語の整形**: Tesseract が入れる文字間スペースを詰める (`山 田 太 郎` → `山田太郎`)。英単語間・列区切りの全角スペースは残す
- **表**: 列が 1 つ欠けた行 (`備考 | (空) | なし`) でも列がずれない／少し傾いたスキャンでも同じ行にまとまる／信頼度の低いゴミ (`|` など) を捨てる
- **読み込み**: 複数ページ PDF・マルチページ TIFF・EXIF で回転した写真・透過 PNG・小さい画像の拡大・壊れたファイル・パスワード付き PDF・対応外の拡張子
- **書き出し**: UTF-8 は BOM 付き (Excel で化けない)・改行は CRLF・Shift_JIS で表せない字は `?`・CSV のカンマや引用符・文字だけ PDF の折り返しと改ページ・検索可能 PDF のページ順
- **設定**: 壊れた JSON・知らない値・型違いでも既定値で起動する
- **実際の OCR**: 紹介状風の画像から `診療情報提供書` `山田太郎` `様` `令和6年4月1日` `128/80` を読む／90° 回転したスキャンを直して読む／表画像が CSV の列になる／画像だけの PDF から検索可能 PDF を作る
- **画面**: 重複・対象外ファイルを除外／壊れたファイルがあっても残りは完了／Tesseract がないときにメッセージ／終了時に設定を保存

## 目標

- 単体テスト対象 (`textutil` `layout` `loader` `exporters` `settings` `processor`) は分岐を含めてほぼ全て通す。`gui` は主要な操作の流れのみ。
- CI (GitHub Actions) で、Linux: 全テスト (Tesseract・日本語フォント・Xvfb 入り)、Windows: 全テスト＋ exe のスモークテスト。どちらかが失敗したら配布物を使わない。

## 自動テストでは確かめられないもの (手で確認)

実際の電子カルテ PC に入れる前に、次を一度確認する。

- [ ] 実物のスキャナで取り込んだ書類 (紹介状・検査結果・処方箋など) を数枚読ませ、目で見て結果を確認
- [ ] 電子カルテ PC の Windows で起動できる (SmartScreen やウイルス対策ソフトにブロックされないか)
- [ ] 日本語の表示・ボタンの大きさが見やすい (高 DPI 画面を含む)
- [ ] ドラッグ＆ドロップ・「コピー」して電子カルテに貼り付け
- [ ] 50 ページ程度の PDF を処理してもメモリ不足にならない／途中で「中止」できる
- [ ] 書き込み権限のないフォルダを保存先にしたときにエラーが表示される

## 既知の弱点 (テストで保証していないこと)

- **手書き文字**は Tesseract では実用的に読めない。
- 表の列分けは「左端の位置」で揃えるため、**右寄せの数字**や**複数列にまたがる見出し**で列がずれることがある。
- 罫線の多い書式や段組みは、TXT の読み順が崩れることがある。
- 実際の診療書類の画像はテストデータに含めていない (個人情報のため)。精度は合成画像でしか自動確認していない。
