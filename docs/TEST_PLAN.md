# テスト計画

## 前提とリスク

使う場所は**ネットにつながらない電子カルテ PC**、使う人は**パソコンに詳しくない利用者**、扱う書類は**診療情報**。
そこから、テストで特に守るものを次の順に決めた。

1. **通信しないこと** — 1 バイトでも外に出たら導入できない
2. **元の書類を壊さない・消さないこと** — 出力で上書きしない
3. **読み取った内容が正しいこと** — 誤認識はゼロにできないので、少なくとも「読めた文字が欠けない・並びが崩れない」
4. **1 ファイルの失敗で全体が止まらないこと**、失敗したら理由が日本語でわかること
5. **exe にしたあとも動くこと** — 開発環境では動くが配布物で壊れる、が一番気づきにくい

## テストの構成

```
        /  配布物スモーク  \     exe + 同梱 Tesseract で 3 形式を実際に出力 (CI の Windows で毎回)
       /  OCR 結合 / 画面   \    本物の Tesseract・本物の Tk で一連の流れ
      /       単体テスト      \   レイアウト・整形・書き出し・設定・読み込み (速い、Tesseract 不要)
```

| 対象 | 種類 | ファイル | Tesseract | 主に守るもの |
| --- | --- | --- | --- | --- |
| 日本語の整形 (`textutil`) | 単体 | `test_textutil.py` | 不要 | 3 |
| 行・列の組み立て (`layout`) | 単体 | `test_layout.py` | 不要 | 3 |
| ファイル読み込み (`loader`) | 単体 | `test_loader.py` | 不要 | 4 |
| 書き出し (`exporters`) | 単体 | `test_exporters.py` | 不要 | 3 |
| 設定 (`settings`) | 単体 | `test_settings.py` | 不要 | 4 |
| 処理の流れ (`processor`) | 単体 (代役エンジン) | `test_processor.py` | 不要 | 1, 2, 4 |
| 実際の文字認識・CLI | 結合 | `test_ocr_integration.py` | **必要** | 3, 4 |
| 画面 | 結合 | `test_gui.py` | 不要 (代役) | 4 |
| exe | スモーク | `smoke_bundle.py` | 同梱版 | 5 |

## 主なテストケース

- **通信しない**: `socket.socket` / `create_connection` を呼んだら失敗するようにして、3 形式すべてを出力 (`test_processing_never_touches_the_network`)
- **上書きしない**: 同名ファイルがあれば `(2)`, `(3)`…、PDF→PDF は `_文字起こし` を付ける
- **日本語の整形**: Tesseract が入れる文字間スペースを詰める (`山 田 太 郎` → `山田太郎`)。英単語間・列区切りの全角スペースは残す
- **表**: 列が 1 つ欠けた行 (`備考 | (空) | なし`) でも列がずれない／少し傾いたスキャンでも同じ行にまとまる／信頼度の低いゴミ (`|` など) を捨てる
- **読み込み**: 複数ページ PDF・マルチページ TIFF・EXIF で回転した写真・透過 PNG・小さい画像の拡大・壊れたファイル・パスワード付き PDF・対応外の拡張子
- **書き出し**: UTF-8 は BOM 付き (Excel で化けない)・改行は CRLF・Shift_JIS で表せない字は `?`・CSV のカンマや引用符・文字だけ PDF の折り返しと改ページ・検索可能 PDF のページ順
- **設定**: 壊れた JSON・知らない値・型違いでも既定値で起動する
- **実際の OCR**: 紹介状風の画像から `診療情報提供書` `山田太郎` `様` `令和6年4月1日` `128/80` を読む／90° 回転したスキャンを直して読む／表画像が CSV の列になる／画像だけの PDF から検索可能 PDF を作る
- **画面**: 重複・対象外ファイルを除外／壊れたファイルがあっても残りは完了／Tesseract がないときにメッセージ／終了時に設定を保存

## 目標と現状

- 単体テスト対象 (`textutil` `layout` `loader` `exporters` `settings` `processor`) は分岐を含めてほぼ全て通す。`gui` は主要な操作の流れのみ。
- 計測: `pytest --cov=scantext --cov-branch`

| モジュール | 目標 (分岐込み) | 現状 (2026-10-22) | 残り |
| --- | --- | --- | --- |
| `textutil` `exporters` `processor` | 95% | 100% | — |
| `layout` `loader` | 95% | 98〜100% | — |
| `ocr` | 90% | 90% 前後 | Windows 専用の探索パス (Windows の CI で通る) |
| `settings` | 90% | 90% 前後 | APPDATA に書けないときの分岐 |
| `cli` | 80% | 80% 前後 | — |
| `gui` | 70% | 78% | ファイル選択ダイアログ・エクスプローラーを開く処理 (手で確認) |
| 全体 | 85% | 87% | |
- CI (GitHub Actions) で、Linux: 全テスト (Tesseract・日本語フォント・Xvfb 入り)、Windows: 全テスト＋ exe のスモークテスト。どちらかが失敗したら配布物を使わない。

## 自動テストでは確かめられないもの (手で確認)

実際の電子カルテ PC に入れる前に、次を一度確認する。

- [ ] 実物のスキャナで取り込んだ書類 (紹介状・検査結果・処方箋など) を数枚読ませ、目で見て結果を確認
- [ ] 電子カルテ PC の Windows で起動できる (SmartScreen やウイルス対策ソフトにブロックされないか)
- [ ] 日本語の表示・ボタンの大きさが見やすい (高 DPI 画面を含む)
- [ ] ドラッグ＆ドロップ・「コピー」して電子カルテに貼り付け
- [ ] 50 ページ程度の PDF を処理してもメモリ不足にならない／途中で「中止」できる
- [ ] 書き込み権限のないフォルダを保存先にしたときにエラーが表示される

## 既知の弱点 (テストで保証していないこと)

- **手書き文字**は Tesseract では実用的に読めない。
- 表の列分けは「左端の位置」で揃えるため、**右寄せの数字**や**複数列にまたがる見出し**で列がずれることがある。
- 罫線の多い書式や段組みは、TXT の読み順が崩れることがある。
- 実際の診療書類の画像はテストデータに含めていない (個人情報のため)。精度は合成画像でしか自動確認していない。

# 問診票モード (手書き対応) のテスト計画

設計: [DESIGN_handwriting.md](DESIGN_handwriting.md) / 決定記録: [adr/0002](adr/0002-handwritten-questionnaire-approach.md)

## 守るもの (優先順)

1. **誤った値が「確定」として保存されない** — 読めない欄は空欄＋要確認になる
2. **チェック欄・○囲みを取り違えない** — 「アレルギー: なし」が「あり」になるのが最悪
3. **違う問診票・違う欄に値が入らない** — 位置合わせの失敗を検出して一般書類モードに戻る
4. **人が直した値がそのまま保存される**
5. 引き続きオフライン (手書きモデルも同梱、通信なし)

## テストデータ

本物の患者さんの問診票は使わない。

| データ | 作り方 | 用途 |
| --- | --- | --- |
| 白紙の問診票 | 実物をスキャン | テンプレート、位置合わせ |
| 合成の記入済み問診票 | 白紙の画像に、チェック・○・数字・文字をプログラムで描き込む。正解が自動で分かる | 単体・結合テスト (CI) |
| ゆがめた合成画像 | 合成画像を回転 (±3°)・拡大縮小・ずらし・JPEG 劣化・薄いインク・影 | 位置合わせとチェック判定の頑丈さ |
| ダミー手書き | 家族が実際に記入 (きれいな字・くずした字・高齢者風・青ペン) 10〜20 枚、正解を CSV で用意 | 手書きエンジンの評価 (手動で実行、CI では使わない) |

## テストの構成

```
         /  評価 (手動)  \          ダミー手書きでエンジンの精度を測る
        / 結合: 合成問診票 \        白紙＋描き込み → 判定 → 確認 → CSV まで (CI)
       /  単体: 部品ごと    \       テンプレート読込・位置合わせ・差分判定・後処理・書き出し (CI)
```

| 対象 | 種類 | 主なケース |
| --- | --- | --- |
| テンプレート読込 | 単体 | 正しい JSON / 欄の座標が範囲外 / 種類の綴り間違い / 選択肢のない choice → 読み込み時にエラー |
| 書式判定・位置合わせ | 単体＋結合 | 白紙そのもの → 一致 / ゆがめた画像で欄の位置ずれが 1% 以内 / 別の書類・白紙ページ → 「一致なし」/ 上下逆 → 向き補正後に一致 |
| チェック欄・○囲み | 単体 | 空 → 未選択 / ✓・×・塗りつぶし → 選択 / ○囲み 1 つ → その選択肢 / 0 個・2 個 → 要確認 / 薄いインク・はみ出し / ゴミ・影は選択にしない |
| 手書き欄の後処理 | 単体 | 数字欄に漢字 → 要確認 / 「令和6年4月1日」「R6.4.1」「2024/4/1」→ 同じ日付 / 年齢 250 など範囲外 → 要確認 / 信頼度しきい値の境目 |
| 手書きエンジンの差し替え | 単体 | 代役エンジンで流れを確認 / エンジンが無い・壊れている → 手書き欄は画像のみで続行 |
| 確認画面 | 画面 | 要確認の欄が上に並ぶ / 修正した値が保存される / 状態が「手入力」になる / 要確認が残っていたら保存前に知らせる |
| 書き出し | 単体 | CSV は 1 枚 1 行・列は質問の順 / 複数枚を 1 ファイルに / 要確認の欄は「(要確認)」/ PDF に確認済みの値 |
| 全体 | 結合 | 合成問診票 10 枚 → CSV が正解と一致 (チェック欄は全問一致が合格条件) |
| 通信しない | 単体 | 現行と同じく socket を塞いで問診票モードを通す |

## 合格の基準

| 指標 | 基準 | 測り方 |
| --- | --- | --- |
| チェック欄・○囲みの正解率 (合成) | **100%** (要確認に回すのは可、取り違えは 0) | CI |
| チェック欄の取り違え (ダミー手書き) | **0 件** | 手動評価 |
| 位置合わせの成功率 (ゆがめた合成) | 99% 以上、失敗はすべて「一致なし」で検出 | CI |
| 自動確定した手書き欄の誤り率 | **1% 以下** (超えたらしきい値を上げる) | 手動評価 |
| 数字欄の自動確定率 | 70% 以上 (下回ったら手書き欄は画像のみで運用) | 手動評価 |
| 1 枚あたりの処理時間 | 30 秒以内 (実機) | 手動評価 |

「取り違え 0」と「確定した値の誤り 1% 以下」を、読める割合より優先する。読めない欄が増えても、確認する人の手間が増えるだけで済むため。

## 手書きエンジンの評価方法

- `tools/evaluate_handwriting.py` (第 2 段階で作る): ダミー手書きの画像と正解 CSV を読み、エンジンごと・欄の種類ごとに次を表で出す
  - 文字単位の正解率、欄単位の完全一致率
  - 信頼度のしきい値ごとの「自動確定率」と「自動確定した欄の誤り率」
- 結果を見てしきい値を決め、ADR-0002 に記録する
- 評価用の画像は個人情報ではないがリポジトリには入れず、PC 内で実行する

## 既存テストで足りないところ

- **実物のスキャンでの精度**は自動テストに入っていない (合成画像のみ)。第 1 段階からは「家族のダミー記入をスキャンしたもの」を手動評価に加える
- **Windows 専用の分岐** (Tesseract の探索パス、エクスプローラーを開く) は Linux では通らない。Windows の CI で全テストを回して補う
- **長時間・大量処理** (100 ページの PDF、50 ファイル連続) のメモリ・速度は未計測。実機で一度測る
